# UI 模块与布局

## 模块职责

| 模块 | 使用目的 | 入口与次级功能 |
| --- | --- | --- |
| 我的清单 | 查看、执行和维护个人清单 | 侧栏主要区域；新建、重命名、任务编辑、子任务折叠、来源与成果 |
| 任务概览 | 跨清单查看任务 | 页内切换今天、收集箱、即将到来、全部任务；今天页进入“安排今日” |
| 待处理邮件 | 接收并确认邮件任务 | 接收处理、运行进度、候选确认与失败恢复；处理规则与用量默认折叠 |
| 导入与规划 | 把文本、文件或目录转换成任务与学习计划 | 选择来源、责任主体、预览确认；高级排程选项默认折叠 |
| 记录与回顾 | 查看成果与历史，恢复或撤销 | 页内切换周复盘、导入历史、操作记录、回收站 |
| 设置 | 配置应用偏好和连接 | 页内切换外观、账户连接、模型服务；模型连接配置和添加表单按需展开 |

“今天”是任务执行视图，“安排今日”负责选择执行日期和每日容量。安排入口放在今天页内，不再作为平级侧栏入口。邮件相关的执行操作只在待处理模块；设置中的 Gmail 已连接态只呈现账户状态。

## 清单显示规则

- 有任务且 `pending_count === 0` 的清单归入已完成分组；空清单保留在普通区域。
- 普通清单保留原顺序；已完成分组排在它们之后，默认折叠。
- 已完成清单用删除线和完成勾标识。
- 分组收起时，当前正在查看的已完成清单仍显示，避免丢失位置。
- 取消完成或新增任务后，刷新数据即可自动回到普通区域，不修改任务或清单数据。

## 布局与样式职责

- `Navigation.tsx` 负责侧栏、清单分组和任务/记录导航。
- `GmailConnectionCard.tsx` 保证 Gmail 已连接态不显示配置与执行按钮。
- `layout.css` 统一应用布局、标题层级、导航、间距和响应式行为。
- `styles.css` 保留基础主题和任务/编辑组件样式。
- `settings.css` 保留设置、导入和排程组件样式。
- `workspace.css` 保留邮件、回顾、安排和来源组件样式。

侧栏和顶栏不跟随正文滚动，清单和正文分别使用自身滚动区。侧栏宽度保留拖动和键盘调整；窄屏侧栏改为抽屉。长清单名在侧栏省略并保留完整提示，正文标题允许自然换行。

## 验证

在仓库根目录执行：

```powershell
npm --prefix frontend run build
npm --prefix frontend run test:ui
```

UI 回归检查使用真实 React 组件的静态渲染，验证导航、清单完成状态变化、当前清单定位和 Gmail 状态展示。它不替代浏览器视觉验收。

可用独立示例数据做本机视觉验收：

```powershell
python frontend/qa/preview_server.py
```

打开 `http://127.0.0.1:4178`，或在另一个终端执行 `.venv/Scripts/python.exe frontend/qa/preview_window.py` 使用桌面程序相同的 WebView2 引擎。预览不读取任务数据库、不访问 Gmail，状态修改仅保存在内存。建议检查 1180×820、较窄窗口与手机宽度，浅色/深色主题，多清单滚动、长标题和各模块切换。

本轮已通过生产构建和功能渲染回归检查。浏览器连接超时，本机自动化也因无法可靠识别浏览器 URL 停止；因此本轮未完成截图视觉验收。
